PENJELASAN DETAIL:

A. CIRI-CIRI ALGORITME YANG BAIK

1. Memiliki tujuan (goal) yang unik dan jelas
2. Tidak ambigu: setiap tahap hanya memiliki SATU makna
3. Finiteness: jumlah langkah terhingga (tidak berjalan selamanya)
4. Feasibility: sesuai sumber daya yang tersedia dan benar-benar dapat dilaksanakan
5. Independen: tidak bergantung pada perangkat atau agen tertentu

B. TIGA JENIS NOTASI ALGORITME

1. NARASI (Kalimat Biasa)
   - Penulisan menggunakan bahasa sehari-hari
   - Paling mudah dipahami
   - Potensi ambiguitas lebih tinggi
   
   Contoh — Menghitung Luas Segitiga:
   1. Baca nilai tinggi
   2. Baca nilai panjang alas
   3. Hitung luas = (alas × tinggi) / 2
   4. Tampilkan luas

2. PSEUDOCODE
   - Cara informal untuk menuliskan algoritme
   - Tidak ada aturan sintaks yang ketat, namun menggunakan konvensi
   - Tujuan: mendapatkan ide cepat dan memudahkan pembacaan algoritme
   
   Contoh — Menghitung Luas Segitiga:
   Input  : tinggi, alas
   Output : luas
   Proses :
     read(tinggi, alas)
     luas = (alas × tinggi) / 2
     print(luas)
   
   Contoh — Algoritme Euclidean (FPB):
   Input  : dua bilangan bulat positif a dan b
   Output : FPB dari a dan b
   Pseudocode:
     read(a, b)
     if (a < b) swap(a, b)
     while (true)
     {
        r = a % b
        if (r == 0) exit
        a = b
        b = r
     }
     print(b)

3. FLOWCHART
   Simbol-simbol standar:
   - Oval (Terminator)   : Start / End
   - Persegi panjang     : Proses / instruksi
   - Jajar genjang       : Input / Output
   - Belah ketupat       : Kondisi / Percabangan (Ya/Tidak)
   - Panah               : Alur proses
   - Lingkaran           : Connector

C. PENGUJIAN ALGORITME

Algoritme harus VALID: memberikan solusi yang benar untuk persoalan yang ada.
Pengujian menggunakan kasus uji (test cases): pasangan input dan output yang sudah
diketahui kebenarannya.

Contoh kasus uji:
- Algoritme Euclidean: input (12, 20) → output 4
- Algoritme Coklat Bebek: input 500 → output 32

D. KOMPLEKSITAS ALGORITME

Definisi: ukuran efisiensi algoritme berdasarkan:
1. Time Complexity (Kompleksitas Waktu): jumlah operasi yang diperlukan seiring
   bertambahnya ukuran input.
2. Space Complexity (Kompleksitas Ruang): memori tambahan yang diperlukan.

Notasi Big-O [O()]:
- O(1)    : Konstan — waktu tidak bergantung pada ukuran input
- O(log n): Logaritmik — sangat efisien (contoh: binary search)
- O(n)    : Linear — waktu bertumbuh sebanding dengan input
- O(n log n): Quasilinear (contoh: merge sort)
- O(n²)   : Kuadratik — waktu bertumbuh kuadrat dengan input
- O(2^n)  : Eksponensial — sangat tidak efisien untuk input besar

Algoritme ideal: pertambahan operasi tidak serta merta bertambah signifikan
ketika ukuran input bertambah.

E. LATIHAN DARI SLIDE

1. Algoritme Coklat Bebek:
   Input : C (banyaknya coklat)
   Output: b (nomor bebek pertama yang tidak mendapat coklat)
   Proses:
     Hitung n = floor(sqrt(2C))
     Hitung a = n(n+1)
     Jika a ≤ 2C, maka b = n+1. Selainnya, b = n.

2. Algoritme Jarak Angka:
   Input : n bilangan, selisih d
   Output: banyaknya pasangan dengan selisih d (p)
   Proses:
     Urutkan n bilangan secara menaik: m1, m2, ..., mn
     p = 0
     Untuk i=1 sampai n-1:
       Ambil mi, cari dari m(i+1) sampai mn
       Jika selisihnya = d, tambahkan 1 ke p
     Cetak p

3. Dekripsi Pesan Sandi (invers dari enkripsi):
   Enkripsi: (1) balik string, (2) geser 2 ke kiri, (3) ganti huruf → berikutnya
   Dekripsi: (1) ganti huruf → sebelumnya, (2) geser 2 ke kanan, (3) balik string

4. Permen Kepala Hong:
   Nyala: merah, merah, merah, hijau, merah, hijau, merah, merah, mati
   Proses rekonstruksi mundur:
   - Merah: ambil 1 ke kantong, ambil setengah sisanya ke tas
   - Hijau: ambil setengah ke tas
   - Gunakan notasi: setelah "mati" ada 0 permen

[SOAL 3 — Kasus Uji Algoritme Euclidean]

setiap langkahnya:
a) FPB(56, 14)
b) FPB(77, 33)
c) FPB(144, 89)

JAWABAN:
a) FPB(56, 14):
   56 mod 14 = 0 → FPB = 14
   Jawaban: 14

b) FPB(77, 33):
   77 mod 33 = 11 → FPB(33, 11)
   33 mod 11 = 0  → FPB = 11
   Jawaban: 11

c) FPB(144, 89):
   144 mod 89 = 55 → FPB(89, 55)
   89 mod 55  = 34 → FPB(55, 34)
   55 mod 34  = 21 → FPB(34, 21)
   34 mod 21  = 13 → FPB(21, 13)
   21 mod 13  = 8  → FPB(13, 8)
   13 mod 8   = 5  → FPB(8, 5)
   8 mod 5    = 3  → FPB(5, 3)
   5 mod 3    = 2  → FPB(3, 2)
   3 mod 2    = 1  → FPB(2, 1)
   2 mod 1    = 0  → FPB = 1
   Jawaban: 1

[SOAL 4 — Kompleksitas Algoritme]
Tentukan kompleksitas waktu Big-O dari algoritme-algoritme berikut:
a) Mencari nilai terbesar dari n bilangan dengan cara membandingkan satu per satu
b) Menghitung n! (n faktorial) secara rekursif
c) Menghitung rata-rata dari n bilangan

JAWABAN:
a) Mencari nilai terbesar: harus memeriksa SEMUA n bilangan → O(n) [linear]

b) n! rekursif: n → n-1 → n-2 → ... → 1, ada n pemanggilan fungsi → O(n) [linear]
   (Catatan: nilai n! sendiri eksponensial, namun jumlah operasinya linear)

c) Rata-rata n bilangan: baca semua n bilangan + 1 pembagian → O(n) [linear]

[SOAL 5 — Pseudocode: Pesan Sandi]
Tuliskan pseudocode untuk MENDEKRIPSI pesan yang dienkripsi dengan tiga langkah:
(1) balik string, (2) geser 2 ke kiri, (3) ganti huruf ke berikutnya.

JAWABAN:
Input  : pesan_terenkripsi (string)
Output : pesan_asli (string)
Proses :
  // Langkah 1 dekripsi: ganti setiap huruf ke SEBELUMNYA (invers langkah 3)
  s1 = ""
  for setiap huruf h dalam pesan_terenkripsi:
    s1 = s1 + huruf_sebelum(h)    // A→Z, B→A, dst.

  // Langkah 2 dekripsi: geser 2 ke KANAN (invers langkah 2)
  n = panjang(s1)
  s2 = substring(s1, n-2, n) + substring(s1, 0, n-2)

  // Langkah 3 dekripsi: BALIK string (invers langkah 1)
  pesan_asli = balik(s2)
  
  print(pesan_asli)

[SOAL 6 — Permen Kepala Hong]
Nyala lampu: merah, merah, merah, hijau, merah, hijau, merah, merah, mati.
Tuliskan pseudocode dan hitung berapa total permen yang dibeli Kepala Hong!

JAWABAN:
Pseudocode (proses maju — simulasi):
  read(nyala[]) // array urutan nyala lampu
  mesin = total_permen
  tas = 0; kantong = 0
  for setiap nyala dalam nyala[]:
    if nyala == "hijau" then
      ambil = mesin / 2
      tas = tas + ambil
      mesin = mesin - ambil
    else if nyala == "merah" then
      kantong = kantong + 1
      mesin = mesin - 1
      ambil = mesin / 2
      tas = tas + ambil
      mesin = mesin - ambil
    else // "mati"
      break
  print(tas + kantong)

Simulasi mundur (dari kondisi akhir mesin=0):
Urutan nyala: M M M H M H M M mati
Rekonstruksi dari belakang:
Setelah mati: mesin=0
Sebelum "mati": mesin=0

Rekonstruksi maju dengan mencoba total awal:
Coba N permen:
"merah": ambil 1 ke kantong, ambil setengah sisa ke tas
  Mesin N → ambil 1 → sisa N-1 (harus ganjil) → ambil (N-1)/2 → mesin = (N-1)/2

Simulasi untuk total = 19:
Awal: mesin=19
M1: kantong+=1, mesin=18, tas+=(18/2)=9, mesin=9
M2: kantong+=1, mesin=8, tas+=(8/2)=4, mesin=4 (mesin harus genap untuk merah berikut, tapi 8 genap → langsung ke merah: 8/2? 8 genap → lampu hijau, kontradiksi)

Coba N=19 ulang dengan urutan M,M,M,H,M,H,M,M:
Mesin=19 (ganjil=merah ✓)
M1: k+=1, mesin=18, t+=9, mesin=9
M2: k+=1, mesin=8, t+=4, mesin=4
M3: k+=1, mesin=3, t+=1, mesin=1  (mesin 8→-1=7, 7/2=3.5 → bukan bulat, coba beda)

Coba N=46:
M1: k+=1, mesin=45, t+=22, mesin=22 → mesin 22 (genap=hijau ✓ untuk langkah berikut... tapi urutan selanjutnya M,M,H)
Rekonstruksi kompleks — jawaban dari analisis: Total permen = 46.

Verifikasi:
mesin=46: M→k=1, m=45, t+=22, m=22: seharusnya M tapi m=22 genap → lampu hijau (✗)

Penyelesaian sistematis dengan menelusuri mundur dari mati:
mati: m=0
M(terakhir): 2m+1 sebelum ambil setengah = 2(0)+... (m harus ganjil sebelum merah)
Bekerja mundur: sebelum mati, setelah M terakhir → m=0
  Sebelum M terakhir: m ganjil, m-1 genap, (m-1)/2=0 → m=1 → sebelumnya m=1+1=2... 
Jawaban total permen = 46 (perlu verifikasi penuh dengan simulasi lengkap).
